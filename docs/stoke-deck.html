The tool

stoke: two engines behind one command.

Claude keeps your conversation cached for a few minutes. Idle past that and the next message pays to rebuild all of it at full price.

Engine 1, prevent

Keep-alive proxy

Sits in front of the API and sends a zero-output ping before the cache window closes, so the conversation stays warm while you are away.

Engine 2, measure

Monitor

Reads every transcript into SQLite, prices each turn, and runs five detectors that name the avoidable charges. Six hooks act on them live, including a hard block above 300k tokens.

What worked

Measurement changed my behaviour more than automation did.

  • Naming the cause in plain language."You walked away and the cache went cold" is something I can act on. "cache_expiry: $246" is not.
  • The 300k hard block.The only lever with a certain payoff. It refuses the message instead of suggesting something, and it has fired on this very session.
  • Making the readout cheap to load.The dashboard went from 437 KB and 66,000 pixels of scroll to 2 KB. One query went from 277 ms to 0.03 ms.
What did not work

The prevention engine barely pays for itself.

  • Keep-alive pings cost 61% of what they save.Last 30 days: $201 of rebuilds avoided, $149 spent on the pings that avoided them. Net $52. It works, but it is not free money, and I built it before I measured that ratio.
  • My first dashboard was unreadable.1,087 rows, and the biggest number on screen was negative 47 cents. I had built it for myself, not for anyone seeing it once.
  • One promised view was impossible.A before and after install comparison. stoke started logging two days before my earliest transcript, so there is no before. I withdrew it rather than fake it.
What I would do differently

Measure first, then build the fix.

  • Prove the ratio before writing the optimiser.The pinger took a weekend. Knowing it returns 1.35 to 1 would have taken an afternoon of counting.
  • Prefer certain levers over probabilistic ones.Blocking an oversized message saves a known amount. Pinging spends real money on a gamble that you will come back.
  • Test against live data, not fixtures.Two bugs passed every unit test and only showed up against the real database.
  • Write the numbers for a stranger from day one.The rewrite that made it readable cost more than the original build.
